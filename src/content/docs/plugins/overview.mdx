Choose a plugin by the work you want it to help with. The bundled examples show how to turn shared records into a useful report, an assigned checklist or a dedicated business workspace. Each guide explains what the example does today, how to try it and how a builder can adapt it.

## Combine plugins into a workflow

Start with the [industry recipes](/docs/recipes) when you want several capabilities to work together. For example, [client engagement onboarding](/docs/recipes/engagement-onboarding) combines a won opportunity, Client onboarding, shared tasks and overdue-commitment review. Each plugin below also has a focused guide for its own setup and behavior.

## Reports that turn records into a useful review

Four examples compute a factual finding without ever calling a model, which is worth noticing: [Business Pulse](/docs/plugins/business-pulse) combines pipeline risks, overdue commitments, and upcoming meetings into one report. [Pipeline follow-up](/docs/plugins/pipeline-watch) surfaces open deals with a stale update or an overdue next action. [Overdue commitments](/docs/plugins/commitment-watch) lists overdue tasks linked back to the work behind them. [Meeting preparation](/docs/plugins/meeting-prep) flags upcoming meetings that need prep time. Together they're a useful pattern for keeping a factual business rule in plain code while still letting AI help interpret what the report found.

## Workflows that create something you can use

Four examples connect a preview to an approval and an execution result, the same loop the rest of the product runs on. [Client onboarding](/docs/plugins/client-onboarding) turns a won opportunity into a reviewed checklist. [Meeting commitments](/docs/plugins/meeting-commitments) turns a meeting into assigned, dated tasks. [Stripe invoicing](/docs/plugins/stripe-invoicing) covers reviewed invoice creation, sending, and customer presentation. [Stripe subscriptions](/docs/plugins/stripe-subscriptions) covers recurring plans, secure checkout and renewal management. Each shows how your own workflow can reuse the platform's task or provider services instead of building them again from nothing.

## Workspaces built around a business process

Two examples go further and become a small business process on their own. [Receivables Collections](/docs/plugins/receivables-collections) brings invoice evidence, payment promises, disputes, and reviewed reminders into one case workspace. [Opportunity Radar](/docs/plugins/opportunity-radar) combines a business profile with source-backed growth and relationship reviews. Both guides are explicit about what's finished today and what the larger extension pattern looks like. [Form builder](/docs/plugins/form-builder) publishes shareable intake forms and holds every response for human review before it enters the pipeline.

## Learning the smallest building block

The [Inventory registration example](/docs/plugins/example-inventory) demonstrates a page, navigation entry, and settings, and nothing more; it's a scaffold for learning module registration, not an inventory product you'd run.

## Building your own

Choose an example close to what you want, read its guide, and follow the linked source. Describe your desired business outcome to a coding assistant along with the records it should use and the approvals it has to preserve, then implement and test a focused change using [the extension guide](/docs/extend). A good extension feels like part of the same workspace, the same customers, the same permissions, a result your team can inspect, and that shared foundation is what frees you to spend your effort on the part that's specific to your business.

## Going beyond the examples

The examples are a starting library you can extend. You can build an App with its own records, a custom lifecycle, its own queue, and a bespoke interface. Follow [the customization path](/docs/customize) to choose between a settings change and a source change, or use [the AI development brief](/docs/extend/ai-authoring) to describe a new App to a coding assistant. General-purpose App creation inside Command Center itself is planned but not shipped; today's path runs through the source repository.

[Site Studio](/docs/plugins/site-studio) is enabled by default in the current module manifest. With the required access, installation owners can create and edit pages, choose an AI model, and explicitly publish or roll back a saved website revision. Private tenant drafts remain separate from the installation website.

[Social Marketing](/docs/plugins/social-marketing) adds source-backed LinkedIn drafts, exact batch approval, a publishing calendar and provider receipts through a separately hosted Postiz service. Its guide explains tenant setup, private images, weekly preparation and recovery from uncertain publication outcomes.
