You can run the real Command Center interface before you've connected a single database or provider, which is the fastest way to decide whether this is worth setting up for real. A connected installation, when you're ready for one, adds your own workspace, authentication, and provider configuration on top of that same interface.

## Explore locally

You need Git, Node.js 22 or later, and npm. Clone the repository and start the app:

```bash
git clone https://github.com/JohnConnorCode/accelerate-site.git
cd accelerate-site
npm ci
npm run dev
```

Open the local URL printed in the terminal, then visit `/demo/command-center`. Choose a fictional business and follow [your first workflow](/docs/start/daily-path). This path does not need email or AI provider keys.

## Start with your own business identity

If you are creating a separate installation, export the neutral starter into a new directory with `node scripts/export-neutral-starter.mjs --output /absolute/new/workspace`. The exporter keeps the shared application and fictional demos while replacing business-owned content with empty collections and neutral placeholders.

Open `src/config/tenant.ts` in that directory and replace the fictional Harbor Operations identity with your own business details. Follow `docs/self-hosting/NEUTRAL-DISTRIBUTION.md` for installation, hosting configuration, the export receipt and verification steps. Your source checkout stays intact, and provider connections remain yours to configure.

## Connect a real workspace

Use a Supabase project and provider accounts you control. Follow [Connect your installation](/docs/self-hosting/installation) for the environment variables, the setup command, and verification steps. For version-specific details, use `docs/self-hosting/SELF-HOSTING.md` in your checkout.

Do not use an existing production database as an installation experiment. The owner identity and migration order matter; skipping a step can leave an account without workspace access.

## Add providers incrementally

Start with one workflow. Connect its providers, then inspect [Setup Center](/docs/workspace/setup). An OpenRouter key enables configured AI workloads; a verified mail connection enables real sending. Neither is required merely to explore the demo.

Before importing real contacts, confirm that you can sign in to the intended workspace and complete a controlled test workflow. Check the action result as well as the screen's success message.

## Keep your installation maintainable

Use the installation and upgrade instructions shipped with your version. Back up your database before upgrades. Keep server credentials in local or hosting-provider secret configuration, not in source control.

For extending the application, start with [Build on it](/docs/extend). For connecting an external assistant, see [MCP client setup](/docs/extend/mcp-clients).
