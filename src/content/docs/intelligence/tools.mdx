When an assistant needs to answer a question or prepare a change, its registered tools define the operations it can request. This catalog is generated from the current registry and includes each tool’s description and input schema, so a builder can inspect the contract behind a request.

Read tools retrieve available context. Proposal tools prepare changes for the workspace’s review process; some approved operations can contact external providers or recipients. Inspect the specific tool and its requirements rather than assuming that every proposal has the same effect.

Availability depends on workspace access, enabled modules, connected providers and action policy. Use [Setup](/docs/workspace/setup) to investigate a missing connection, [Approvals](/docs/command-center/approvals) to understand a proposed change, and [MCP clients](/docs/extend/mcp-clients) to connect an external assistant.

For task changes, `propose_task_update` prepares completion, reopening, snoozing, or edits to the title, description, priority and due date. An empty description or due date clears that value. The proposal records the current task details so execution can refuse intervening edits. Follow [the task review steps](/docs/command-center/work#updating-a-task-with-ask-ai) to inspect and approve the change.

## Reports and exports

Ask “Show our recorded revenue by client” or “Compare the funnel for website leads over the last 30 days.” `get_revenue_report` and `get_revenue_analytics` use the same reporting services as Revenue and Analytics. Revenue sections include the summary, clients, industries, timeline and definitions. Analytics sections include the summary, funnel, forecast, source breakdown, quality, filter options and website activity.

Analytics accepts a creation window from 7 to 365 days and named source, owner, campaign and stage filters. Opportunity filters describe the opportunity cohort; website activity accepts the day window only and refuses opportunity filters. Drilldowns return up to five rows per page, with a total and `nextOffset` for continuation. A missing or incomplete source is disclosed rather than presented as a complete total.

`export_revenue_report` and `export_revenue_analytics` return the requested section or page as JSON or field/value CSV, including its filters and quality information. An export is not an entire database dump, a published file or an email attachment. An external client can save the returned content. Recorded contracts, accepted proposals, won opportunity value and forecasts have different meanings; none establish cash collected, and reporting does not convert currencies.

`get_admin_operation_coverage` searches the current tool catalogue and shows reviewed operation mappings. These mappings connect tools to their shared service and verification evidence. Tool counts and route counts do not establish universal access. The capability screen also separates module registration from the permissions and connections checked when a tool runs.

## Workspace configuration

`get_workspace_configuration` returns redacted provider status, Drive folder selections and named public preferences. `preview_workspace_configuration` prepares exact before and after values without changing configuration. `propose_workspace_configuration` stages that unchanged preview for human approval in Work.

Supported changes cover provider disconnect, selected Drive folders, named public preferences, bounded Google sync and Google connection verification. Branding and optional module controls use their existing dedicated tools. Secrets, OAuth consent, one-time keys and installation authority require secure human setup. The tool catalog describes supported operations; universal conversational coverage remains in progress.

## Ordered work and internal permission

`preview_agent_work` validates an ordered plan. `start_agent_work` saves that exact preview with a stable request ID; `get_agent_work` returns its saved progress, and `control_agent_work` pauses, resumes or cancels future steps against the current revision. These tools require an authenticated member, an active scheduler and a finite AI call budget for background execution. Starting a plan grants no business permission.

`preview_internal_permission` and `propose_internal_permission` prepare a human decision for internal operations on named records, allowed fields, a daily limit and an expiry. The model has no approval tool. A current approved permission can let a covered proposal execute through the shared action service; otherwise it remains pending.

`propose_next_action` prepares an opportunity's next action with a check against the values the agent read. Another person's edit requires a fresh proposal.
