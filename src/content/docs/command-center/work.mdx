Open **Tasks** from the Command section to see the work a person owns. Use **Today** for the small set of items that need attention now; both views point to the same task or approval record.

## Two kinds of work

| View | Use it for | What happens there |
| --- | --- | --- |
| Tasks | Work someone must do | Complete, snooze, open context, or follow the source record. |
| Approvals | A proposed change needs a decision | Review the evidence and exact effect, then approve or reject. |

An email send, stage change, or invoice reminder is an **Action** inside an approval. It is not a second task. When an approval creates tasks, the approval resolves first and the new tasks keep their own IDs and history.

## A useful morning path

1. Open [Today](/docs/command-center/today) and choose the state that matches your attention: Do, Approve, Decide, or Consider.
2. Complete a task only after checking its owner, due date, and linked record.
3. Open an approval to see the proposed recipient, change, policy, and provider result before anything consequential runs.
4. Use [Activity](/docs/command-center/activity) when you need the durable receipt of what happened.

Apps can add a domain-native work type when its lifecycle is materially different. The source object remains authoritative; Today and Tasks only project it. This keeps a collections case, creative review, or onboarding checklist from becoming a duplicate task queue.
