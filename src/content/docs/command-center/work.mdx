---
title: "Manage tasks and approvals in Work"
description: "Edit commitments and review decisions while keeping one saved task or approval across views."
updated: "2026-09-07"
---

Open **Work** in the Command Center navigation, or visit `/admin/work`. The Tasks and Approvals views read the same records used by Today and the existing business workflows.

## Find and edit a task

1. Open **Tasks**. Choose **Team work**, **My work** or **Unassigned**, then select an open, snoozed or completed status.
2. Filter by source or search the task title and related record name. The list shows up to 100 tasks for the selected ownership and status.
3. Select a task to open its inspector. Edit its title, due date or priority and choose **Save changes**.
4. Return to Today and confirm the changed task where it is due. An edit keeps its existing status; it does not complete the task.

Use the completion control when the work is finished. Today also offers snooze until tomorrow. A snoozed task remains available in Work's **Snoozed** view. Completing it clears the snooze and records completion against the original task ID.

The ownership filter does not assign tasks. Assignment follows the existing workflow that created the task. Custom App cases can keep their own native queues and lifecycle.

## Review a decision

Open **Approvals**, select the proposal and inspect the exact content, target and consequence. Today and Work use the same review inspector and execution service. A successful decision removes that pending approval from both views; it does not create a second approval record.

Read [approval results](/docs/command-center/approvals) before interpreting a provider action. Approval, execution and delivery are separate facts.

## Check the saved result

[Activity](/docs/command-center/activity) retains the recorded changes. A task completion does not confirm a payment, send an email or accept a business proposal. Open the relevant App or source record for those results.

If saving fails, the inspector keeps your input and displays the error. Refresh the record before retrying a stale operation. If a filter looks empty, check ownership and status; an empty filtered list does not mean the workspace has no work.

The fictional demo uses these same pages with isolated session data. Task edits, snoozes and completion persist within that demo session and reset with the workspace.
