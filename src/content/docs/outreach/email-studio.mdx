When a customer says they never received your email, the useful next step is not resending it and hoping, it's checking exactly what your system tried to send and whether the provider actually accepted it. Open `/admin/emails` for that: three views share the page, templates, send history, and a composer for a direct follow-up.

## Templates

Drafts stay protected until you explicitly publish a revision, and preview and test sends use the exact same rendering path as production, so a test that looks right in the composer is genuinely the template that will go out to a customer.

## History

This is what actually left the building, with each send's provider receipt attached. Open a row whenever a contact says they never got the mail; a missing provider id there tells you the send either failed outright or is still uncertain, which is a different problem than a customer's spam filter.

## Composer

A one-off follow-up you write from this screen still goes through the same communication sender with the same idempotency key as everything else, and it still obeys [campaign](/docs/outreach/campaigns) stop rules for anyone who has unsubscribed, so a manual send can never accidentally reach someone who opted out.
