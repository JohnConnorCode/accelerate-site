A customer needs a clear scope and price before deciding whether to proceed. **Proposals** keeps drafts, shared versions and customer decisions together, with catalog validation and a history of changes. Use [Drafting and sending](/docs/proposals/send) to prepare and share a proposal.

## The lifecycle

A proposal moves through create, edit, send, view, accept, and decline, and its public view and decision links are unguessable tokens rather than sequential IDs a stranger could guess. Every one of those events writes an audit row as it happens; the proposal's actual body is not stored inside that audit payload, so the audit trail proves an event occurred without duplicating the content itself.

## Keeping follow-up visible

An unanswered proposal shows up on [Today](/docs/command-center/today) and in [Inbox](/docs/command-center/inbox), so the next action for it lives on the opportunity where anyone can see it, not only in whichever person's memory happened to send it.
