Open `/admin/site` to create page drafts for the public website. A draft is private working copy: it never appears on the public site until a future publish step, which is still being built.

## Create a draft

1. Enter the service name, the audience, and the outcome the page should sell, for example “Bookkeeping automation”, “Home service owners”, “The office runs while the crew builds”. Leave the URL slug blank to derive it from the service name, or set it explicitly when a draft already uses that slug. Use Additional direction for constraints the draft should reflect, such as tone or sections to emphasize.
2. Choose **Built-in service template** for an instant structured draft, or **AI generated** to have the configured model write one (needs OpenRouter connected under Setup).
3. Optionally attach approved catalog photography. Only catalog images can be attached; external URLs are refused.
4. Select **Create draft** and confirm the preview opens with your heading, sections, calls to action, and images.

AI drafts can be refused before they save: invented links, prices, percentages, client names, or non-catalog images come back with the exact problem named. Fix the brief and try again.

## Review the preview

Check the heading, body copy, calls to action, and every attached image with its alt text. Switch between Desktop, Tablet, and Mobile widths. Rename the draft from the same page when the title needs work; if someone else changed the draft underneath you, the save is refused and the latest copy reloads instead of overwriting. A draft that fails validation shows an error instead of a preview; the attached-images list names each catalog reference so you can spot an unresolved one.

Drafts keep a checksum and source record (template or AI) with the brief that produced them. Publishing, scheduling, and rollback arrive in a later release; treat every draft as unapproved until a person has reviewed it.
