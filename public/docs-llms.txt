## Build on it
For coding agents and humans: add a module, an integration adapter, a plugin, or an MCP client without forking core.

- [Extend the runtime](https://www.acceleratewith.us/docs/extend/overview) (updated 2026-09-04): What every extension inherits: approval, audit, module gating, and MCP.
- [Add a module](https://www.acceleratewith.us/docs/extend/modules) (updated 2026-09-04): Register a JSON manifest and pages. Nothing in extensions/ is executed.
- [Add an integration adapter](https://www.acceleratewith.us/docs/extend/adapters) (updated 2026-09-04): Verify credentials, encrypt them, and turn inbound events into canonical records.
- [Plugins](https://www.acceleratewith.us/docs/extend/plugins) (updated 2026-09-04): Register a plugin manifest with tools and triggers that still go through governance.
- [Add an AI tool](https://www.acceleratewith.us/docs/extend/tools) (updated 2026-09-04): Register a schema, an impact tier, and a service boundary. Mutating tools propose.
- [MCP concepts](https://www.acceleratewith.us/docs/extend/mcp) (updated 2026-09-04): Bounded reads, staged writes, tenant isolation. The same registry the UI uses.
- [Connect an MCP client](https://www.acceleratewith.us/docs/extend/mcp-clients) (updated 2026-09-05): Connect an external assistant to the intended workspace and verify a read first.
- [Inbound webhooks](https://www.acceleratewith.us/docs/extend/webhooks) (updated 2026-09-04): Tenant-scoped public routes, signature checks, replay windows, and canonical ingest.
