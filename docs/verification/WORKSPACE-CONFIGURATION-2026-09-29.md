## Shared execution and failure checks

- Registry v26 exposes the three configuration tools in every initial pack under core-system. Existing tool dispatch, module/permission/MCP gates remain authoritative. No second dispatcher, SQL tool, HTTP mutation tool or AI self-approval.
- Preview seals tenant, normalized change, target revision, current/proposed values and consequences. Proposal requires the exact digest and expires after one hour. Approval rechecks current human admin membership, tenant, payload digest and configuration revision.
- Direct admin adapters establish authenticated request context and invoke the same service. SQL row locking/CAS and settings advisory lock protect concurrent/absent-row saves. Audit failure rolls back the configuration write.
- Sync/check job receipts use a deterministic action key. Partial work retains the action progress receipt and fails completion. Reapproval requires a new exact preview, and a bounded incomplete-source retry must first inspect existing source receipts.
- Fictional demos share the same typed change and semantic preview contract, existing business session storage, Work route and ActionReviewDialog. They simulate effects without calling a model or provider. This proves the transport/UI; it does not establish model interpretation accuracy or real provider readiness.
