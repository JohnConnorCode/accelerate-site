# Command Center documentation ownership and verification

The working documentation was found in `agent/docs-command-center`, including
uncommitted content and navigation changes. The founder explicitly directed its
takeover. A local snapshot preserved the existing edits before implementation.
The 50-page expansion is now committed and reconciled with the verified
`agent/production-integration` baseline at `0e39bfd`.

The docs loader reads `src/content/docs`, not database content. A read-only
inspection of the configured database's exposed schema and targeted document
metadata found no separate public docs collection. No database rows were changed.

## Orientation and writing

| Before                                                                  | After                                                                                             |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Start described an agency engagement.                                   | Start explains product value and leads into a fictional first-workflow tutorial.                  |
| The overview mixed positioning and architecture.                        | A task-to-screen map explains where to work and how AI fits.                                      |
| Operational pages often stopped at system descriptions.                 | Key guides explain prerequisites, actions, results, and recovery, including a sample contact CSV. |
| Manual actions and AI proposals were described as the same queue entry. | Approval, manual sending, execution, and delivery are distinguished.                              |
| MCP setup mixed tenant-key and service-role paths.                      | Tenant HTTP access is the default; the local administrative runner's different scope is explicit. |
| The tutorial had no visual context.                                     | `DocsFigure` reuses a labeled fictional Today screenshot with a full-size link.                   |

## Navigation and reference design

| Before                                                                  | After                                                                                              |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| No dedicated docs search; guide bodies were not indexed.                | `DocsSearch` uses the shared public index, filtered to docs, with body and generated catalog text. |
| Identifier queries loosely matched unrelated prose.                     | Exact tool identifiers filter to entries containing that identifier.                               |
| Search failure had no docs-specific recovery surface.                   | Visible loading, empty, error, retry, clear, and keyboard navigation paths.                        |
| Small sidebar targets and two current-page markers on overview routes.  | Targets are at least 40px and the actual page owns the active marker.                              |
| Faint table-of-contents links.                                          | Stronger inactive-link contrast, a named navigation landmark, and current-location semantics.      |
| Mobile placeholder clipping and duplicate clear controls in initial QA. | A shorter placeholder and one visible clear button.                                                |
| Tool reference listed descriptions and impact only.                     | Expandable input schemas, tool packs, and connection requirements.                                 |

## Maintainability and verification

| Before                                                          | After                                                                                                |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Page summaries could drift between MDX, navigation, and search. | The docs verifier requires titles and descriptions to agree.                                         |
| No dedicated docs interaction gate in the integrated CI.        | `test:search` and `qa:docs` run in CI; browser evidence is retained.                                 |
| This older checkout used the heavy legacy Git hook.             | The established staged-only hook and resource-safe baseline are installed.                           |
| Existing work was uncommitted on an older runtime.              | Saved in `45a5916`, then reconciled in `55698aa`; no deployment or live-board completion is implied. |

Local verification includes docs integrity, generated index freshness, search
regressions, scoped lint, and the architecture contract. The first full remote run
for `fe15e26` passed all jobs, including 16 docs browser check groups. Its screenshots
were inspected and informed the final visual refinements. The PR records the final
commit's CI result and screenshots, including image loading, keyboard navigation,
and dark-mode checks added during review.

The previous docs development server on port 3025 stopped responding and was
terminated after confirming its process and worktree ownership. Other servers were
preserved. Full builds and final browser verification use remote CI. Production
publication and live Feature Board handoff remain separate actions.

See [the maintenance contract](../contributing/DOCUMENTATION.md) for future edits
and [PR #32](https://github.com/JohnConnorCode/accelerate-site/pull/32) for final evidence.

## Audience adoption paths

| Before                                                             | After                                                                                                                                                 |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Landing cards repeated section names and guide counts.             | Three audience cards explain the outcome and link directly to business owner, agency, and developer paths. All sections remain available below.       |
| Readers assembled their own adoption sequence.                     | Five new guides cover a business pilot, client provisioning and handoff, a beginner's first code change, connected installation, and troubleshooting. |
| Connected setup required leaving the docs library.                 | An indexed installation walkthrough explains owner creation order, configuration, migration checks, and readiness.                                    |
| Extension prose confused verifier registration with authorization. | It requires runtime module guards in every API handler as well as verifier coverage.                                                                  |

Sources checked against this branch include the canonical self-hosting guide,
`.env.example`, the tenant directory and lifecycle service, the Inventory example,
and the module route guard verifier. These guides distinguish supported mechanisms
from readiness proof and do not claim a deployed installation has passed isolation.
Search regressions cover all five guides. Browser QA follows all three audience
links and returns with Back at both widths, and renders the five new pages.
