# Runtime architecture audit, September 4, 2026

The audit starts at commit `5afd3781cb3cf3a7b26ddad25f27d6e5e5b5fdf4` and covers changes since August 29, 2026, America/Chicago. The [inventory](audits/2026-09-04-runtime-inventory.json) records every reachable commit, changed path, and unique local branch at capture time. It separates complete inventory/static scanning from targeted behavioral inspection. It does not claim exhaustive manual review, production database verification, or production latency measurements.

The northstar requires shared business services, tenant ownership, durable work, explicit authority, trustworthy receipts, and provenance. New coworkers and plugins can continue alongside consolidation, provided their entrypoints use these boundaries. The Feature Board remains the only implementation queue; this document is an audit receipt.

The captured inventory contains 129 commits, 928 touched paths (including changes later reverted), 865 net changed paths, and 12 local branches with unmerged work. Highest priority is tenant isolation, followed by authority and durable execution receipts; duplication and performance follow those correctness boundaries.

## Remaining acceptance boundaries

The consolidation does not certify broader existing cards as shipped. Remaining route-owned writes are enumerated by function/table/operation in `scripts/runtime-write-baseline.json`; a new operation cannot hide inside an exempt file. Proposals, campaigns, leads, bookings, provider settings, and the other legacy routes retain their existing card ownership. The task slice is the first migrated write family.

The plugin isolate and capability-data API pass their primitive tests, but host invocation remains separate acceptance. UI restructuring, screenshot QA, real browser performance, full Sales lifecycle proof, provider receipt reconciliation, and all six resource kinds being instrumented end to end remain visible acceptance gaps. The audit inventory lists unmerged branch work, including Gmail, Drive, identity, documentation, and QA changes; preserving those branches is intentional. No readiness assumption or blind merge substitutes for their acceptance evidence.

## Validation and release contract

Run `test:runtime-consolidation`, `test:runtime-postgres`, `test:core`, `test:ai-tool-gates`, `test:action-reversibility`, `verify:runtime-boundaries`, `verify:agent-contract`, typecheck, strict lint, and build. Disposable PostgreSQL runs the new migrations twice and proves shared coworker names, foreign-link refusal, membership checks, signed policies, global hard floors, budget contention, concurrent work claims/recovery, retry delays, replay, and suspension. In-memory tests prove service behavior; they do not replace PostgreSQL evidence.

Five ordered migrations accompany the code: runtime budget claims, policy enforcement, tenant boundaries, work approval links, and work claims. Apply all five to the named environment before activating this application revision. No production migrations, provider activation, real-recipient tests, or deployment are authorized by this audit receipt. A release requires the founder's explicit production instruction and the exact verified commit.

## Verification evidence

The deterministic runtime, action execution/reversibility, AI tool gates, OpenRouter retry, job/task, module/extension, and core contract suites pass. Disposable PostgreSQL 14 runs all five migrations twice and tests concurrent work claims/recovery, budget contention, tenant isolation, suspension, and policy precedence. TypeScript, strict ESLint, architecture checks, and the production build pass locally. Provider calls are stubbed in tests; these checks establish local behavior rather than production activation.

Performance evidence is deliberately narrow: a three-capability preflight makes one database query, and task mutations use one task read plus one conditional task write. These are query-count improvements, not claims of measured production latency. No browser or database load benchmark is claimed.

Repository-wide formatting exposed 62 files with style drift, including generated reports. Report generators now produce Prettier-compatible output so regeneration cannot reintroduce that conflict. Dependency auditing reports no production dependency advisories; a moderate development-only `@humanfs/node` advisory remains in the inherited lockfile, outside runtime behavior.
